# 移植メモ

MATLAB 版から何を変え、何をあえて変えなかったかの記録。

原則として、**比較が目的なので既定では MATLAB の挙動を再現する**。
明らかな不具合であっても、勝手に直すと「差が実装のせいか移植のせいか」が
分からなくなるため、修正はフラグで切り替える形にしてある。

例外として、計算結果に影響しないもの（未初期化変数の参照、暗黙の前提の検証）は
黙って直している。

---

## `wordTV2WmorphingEngineRev.m`

### 既定で再現する不具合

#### 1. 空の `catch` によるフレーム欠落（147-162 行）

```matlab
try
    spectrogramRefOnTFMrh(:, jj) = interp1(...);
    ...
catch
    %keyboard;
end
```

`interp1` が失敗するとそのフレームは 0 のまま残る。後段で `10^(0/10) = 1`
（平坦 0 dB）、`exp(0) = 1`（完全非周期）になるため、そのフレームだけ
広帯域ノイズになる。エラーも警告も出ない。

`Options::emulate_catch_dropout`（既定 `true`）で再現する。発生数は
`Output::n_dropped_frames` に入り、0 でなければ警告が出る。

#### 2. 区間ループの off-by-one（130 行）

```matlab
if ii == nAnch
    endP = nFrameMorph;
```

`tAnchMrph` は `nAnch+2` 要素なので、ここは `ii == nAnch+1` が正しい。
現状では最後から 2 番目の区間で `fractionV` の分母が過大になり、
周波数ワープの時間補間がその区間だけ遅れる。

`Options::fix_segment_end_index`（既定 `false`）で修正版になる。
影響の大きさは隣接する周波数写像の差に依存し、アンカーが似ていれば
ほとんど効かない。`--fix` 付きで実行して差分を取れば見積もれる。

#### 3. 全フレーム有声への固定（45 行）

```matlab
vuv = double(vuv > 0.3);
vuv = vuv*0 + 1; % all voiced
```

直前で計算した VUV を捨てている。デバッグ時の書き換えが残ったように見えるが、
出音に直接効くので既定では再現する。`Options::force_all_voiced` で無効化できる。

#### 4. 非周期性の低域整形（169-181 行）

モーフィング後に、平均 F0 以下の非周期性を −60 dB 減衰させ、
3×平均 F0 まで余弦で滑らかに戻す。不具合ではなく意図的な処理だが、
`generalizedTCmorphing` には無いので明示的に切り替えられるようにしてある
（`Options::apply_aperiodicity_shaping`）。整形前の値は
`Output::aperiodicity_unshaped` に残る。

### 再現しているが不具合ではないもの

#### 複素対数（20, 77 行）

```matlab
real(exp((1-mStr.fx)*log(diff(tmpLogFanchRef)) + mStr.fx*log(diff(tmpLogFanchTgt))))
```

負値の `log` が複素数になることを利用（あるいは黙認）している。実部を取ると

```
exp((1-w)log|a| + w log|b|) · cos(π·((a<0)(1-w) + (b<0)w))
```

となり、片方だけ負なら 0 になる。逆転したアンカーがあっても破綻しないのは
この性質による。C++ では複素数型を使わず、上式を直接評価している。
`0 * (-inf) = NaN` も IEEE と MATLAB で一致するのでそのまま任せている。

#### `safeguard`（135 行）

```matlab
safeguard = cumsum(ones(n,1)*0.0001);
% This is a quick and dirty fix. Practicall, OK.
```

補間格子に 0.0001 刻みのランプを足して強制的に単調化する。
作者自身が応急処置と認めているが、これが無いと動かない入力があるため再現する。

### 直したもの

#### `interp1` の非単調な格子

MATLAB の `interp1` は `x` が昇順でない場合、`x` と `y` をまとめてソートしてから
補間する。本移植も同じ扱いにした。ただし**これは MATLAB の版によっては例外に
なる可能性がある**。該当箇所があると `Output::n_unsorted_interp` に件数が入り、
警告が出る。

#### 表記の誤り（156 行）

```matlab
fxMorphMapTgtIntrp(:, jj)++safeguard
```

`+(+x)` と解釈されるので結果は変わらない。移植では単に `+` にした。

#### 未使用コード（97-105 行）

`segHead` は計算されるが使われていない。移植では省いた。

### 直していないが注意が要るもの

- 61 行の `fxTgT` が `spectrogramRef` のサイズを使っている。参照と目標で
  FFT 長が違うと壊れる。移植ではビン数の不一致を例外にして先に弾く。
- 171 行の `min(f0_original(f0_original > 30))` は、全フレームが 30 Hz 以下だと
  空配列になる。移植では明示的な例外にした。

## `generalizedTCmorphing.m`

### 直したもの（結果に影響しない範囲）

#### 1. ループ変数の残留値（122-124, 165 行）

```matlab
spGram = worldParameter(1).spectrum_parameter.spectrogram;
```

`worldParameter` は直前のループで最後の素材に束縛された変数。
`nFreqVector` も同様。全素材で標本化周波数・ビン数・アンカー本数が
揃っていれば結果は同じだが、暗黙の前提になっていた。

移植では素材 0 から明示的に取得し、全素材の整合性を検証して
不一致なら例外を投げる。

#### 2. 最終フレームの取りこぼし（234 行）

`while` の条件が厳密不等号のため、最終フレームが最終アンカーと
一致すると未処理のまま残り、`exp(0) = 1` になる。移植では埋めている。

#### 3. VUV 閾値の食い違い（104 行 0.99 / 271 行 0.995）

`morphedVUV` が 0.99 〜 0.995 のフレームは `f0 > 0` なのに `vuv = 0` という
不整合な状態になる。移植では `vuv_threshold` と `vuv_output_threshold` に
分離して意図を明示した。既定値は MATLAB と同じ。

#### 4. 重みの検証

対数領域で混ぜるため各重みベクトルの和は 1 でなければならないが、
MATLAB 版は検証していない。移植では和が 1 でなければ例外を投げる。

### モーフィング後アンカーの逆転

素材ごとの周波数アンカーが逆転していても計算は成立する（補間の y 側に
入るだけで、折り返すワープ関数になる）。単調性が要求されるのは
モーフィング後のアンカー位置（x 側）で、こちらは素材間の重み付き和なので
片方の逆転は打ち消されることが多い。

打ち消されずに残った場合、移植では対数周波数で最小間隔だけ押し広げて続行し、
`MorphOutput::warnings` に記録する。`MorphOptions::repair_nonmonotonic_frequency`
を `false` にすると例外になる。

MATLAB 版はこの状況を想定しておらず、`interp1` の挙動次第で結果が変わる。

## 実装上の判断

### 行列の向き

スペクトログラムを `MatrixXd(n_fbin, n_frame)` とし、Eigen の既定の列優先と
組み合わせて「1 フレーム分が連続メモリ」になるようにした。両エンジンとも
時間方向の整列（隣接 2 列の線形結合）と周波数方向のワープ（1 列内で完結）が
主要な処理なので、この向きが最も効率がよい。

### 非単調な問い合わせ列

逆転したアンカーは折り返すワープ関数を生む。走査ポインタを前進させるだけの
実装だと黙って誤った値を返すため、後退もさせている。単調な入力では
従来どおり O(n + m) のまま。

```cpp
while (i + 2 < n && q >= x[i + 1]) ++i;   // 前進
while (i > 0 && q < x[i]) --i;            // 後退
```

### 並列化

`GeneralizedTCMorphing` はフレームを外側ループにして、各フレームの計算が
独立になるようにしてある。OpenMP があればフレーム方向に並列化される。
`WordTV2WMorphing` は区間ごとの逐次処理なので並列化していない。

## 合成側の注意

pyworld は「フレーム数 × フレーム周期」の長さの波形を返すが、MATLAB の
`Synthesis` は最終フレーム時刻ちょうどで終わる。そのままだと常に
1 フレーム分（5 ms）長くなるので、`tools/synthesize_cpp.py` は末尾を
`temporal_positions[-1] * fs` サンプルに切り詰めている。
